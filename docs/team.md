они неизвестны, имена ниже не являются логинами для CODEOWNERS.

Татьяна остаётся вторым разработчиком алгоритма. Ей выделяется меньший объём production-кода,
чтобы после готовности проверок переключиться на QA. Каждый разработчик пишет и запускает
проверки своей функции; Татьяна не тестирует весь проект в одиночку.

Ориентир для планирования, а не гарантия: F1 65-80 ч, F2 65-80 ч, B1 75-90 ч,
B2 80-95 ч, A1 70-90 ч, A2 35-45 ч алгоритм + 30-40 ч QA за весь период.
На первом созвоне участники оценивают задачи; через неделю пересчитайте остаток по факту.
На переход с C# на Python Руслане, Варваре и Татьяне заложено 6-10 ч внутри этих оценок.
Андрей проводит короткий совместный разбор окружения, типов, pytest и исключений.

## Общие файлы

- F1: frontend/package*.json, frontend конфигурация и маршруты.
- B1: DTO, миграции и docs/api.md; изменение согласует с F2, B2, A2.
- B2: backend/pyproject.toml, uv.lock, compose.yaml, infra/, .github/workflows/.
- A1: контракт RenderSpec и рендер; A2: validation/fixtures/test-plan.
- Документацию функции обновляет её автор, README собирают Руслана и Татьяна.

## Как сотрудничать

Каждый день коротко: что готово + PR, следующий результат, блокер.
Два раза в неделю 30-45 минут: вместе запускаете текущий develop.
Ответ на review - в течение следующего рабочего дня. Блокер дольше дня разбирается парой.
Одна активная основная задача на человека; PR обычно рассчитан на 1-2 рабочих дня.
Координатор интеграции - Варвара, резерв - Руслана. Это дополнительная обязанность, не седьмая роль.

| Передача | Что передать | Кто принимает |
| --- | --- | --- |
| B1 → F1/F2 | JSON request/response + ошибки + OpenAPI | Илья и Леонид проверяют UI-запросом |
| A2 → B1/F2/A1 | Одинаковые правила миллисекунд и invalid fixtures | Руслана, Леонид, Андрей запускают свои проверки |
| A1 → B2 | render_video + CLI + короткий воспроизводимый пример | Варвара вызывает из worker |
| B2 → F1 | job lifecycle и URL видео, сбой/повтор | Илья проверяет все четыре статуса |
| Все → A2 | SHA, сценарий, известные ограничения | Татьяна фиксирует pass/fail и дефекты |
| A2 → все | Дефект с шагами, ожидаемым/фактом, средой | Владелец исправляет, другой участник делает ретест |

Вклад фиксируется содержательными коммитами, issues, review и отчётами. Таблица вклада
перед релизом: имя, GitHub-логин, 3-5 основных PR/issues, результат.
