# Алгоритм и QA: план по функциям

Номера с точкой (например, A1.01) обозначают шаги по функциям.
ID с дефисом в backlog/GitHub обозначают более крупные задачи; это разные уровни плана.

**A1 - Андрей**, **A2 - Татьяна**. Татьяна также координирует QA: после подготовки
валидации, ffprobe и fixtures у неё меньше production-кода, чем у остальных.
Каждый автор тестирует свой код; приёмку функций Татьяны делают Андрей и Руслана.
Татьяна не утверждает собственные изменения единолично.

Этот документ описывает будущую работу. Уже реализованы dataclass-контракт,
`validate_spec`, CLI-вход и генератор синтетического WAV. ASS, ffprobe, FFmpeg
и `render_video` пока завершаются `NotImplementedError`. Успешные проверки
валидации не означают готовность видео.

## Порядок и контрольные точки

1. **До 13 ноября:** A1+A2+B1+B2 согласуют JSON и правила; A2 готовит fixtures,
   A1 проверяет FFmpeg/libass и шрифт в Linux-контейнере с B2.
2. **14-20 ноября:** A1 делает ASS и CLI-рендер, A2 параллельно делает probe/audio validation.
3. **21-27 ноября:** A1+B2 соединяют worker с renderer; A2 проверяет настоящий MP4 через сайт.
4. **28 ноября - 6 декабря:** полный ручной сценарий, текстовые границы, ошибки и повтор.
5. **7-20 декабря:** A2 ведёт регрессию и замеры; Андрей/Руслана принимают её код.
6. **21-27 декабря:** чистый запуск, итоговый SHA, тест-отчёт и релиз. 28-31 декабря - резерв.

## Сначала общий контракт

Файл `backend/renderer/models.py`, владелец A2; изменения согласуют A1 и B2.

| Объект | Что содержит | Как использовать |
| --- | --- | --- |
| `LyricLine` | `id`, `text`, `start_ms`, `end_ms` | Время только целыми мс, null сюда не передавать |
| `RenderSpec` | `style`, `duration_ms`, `lines: tuple[LyricLine, ...]` | Неизменяемый снимок одной генерации |
| `RenderResult` | `path`, `duration_ms`, `width`, `height`, `elapsed_seconds` | Worker сохраняет итог, API строит URL отдельно |
| `MediaInfo` в `ffmpeg.py` | длительность, кодеки, ширина/высота | Результат ffprobe, а не доверие расширению файла |

B1 хранит незаполненные тайминги в черновике как null. B2 перед запуском проверяет
готовность и создаёт отдельный снимок; редактирование проекта не меняет текущий job.
Renderer не импортирует FastAPI, SQLAlchemy или Redis. В API нельзя отдавать внутренний `path`.

## A2.01. `RenderValidationError.__init__` и `validate_spec`

**Файл:** `backend/renderer/validation.py`. **Статус:** реализованы.

- **Вход/выход:** `RenderSpec -> None`; ошибка `RenderValidationError(field, message)`.
- **Что сделать:** проверить действующие правила вместе с B1/F2, расширять только по
  согласованному контракту. Сейчас: стиль brat, 5000..60000 мс, 1..100 строк,
  непустой текст до 120 символов, непустые уникальные ID до 64 символов, целые времена, минимум 100 мс,
  порядок и отсутствие пересечений. Смежные строки и паузы разрешены.
- **Проверка:** `backend/tests/test_renderer_contract.py`; дополнить сравнением
  одинаковых invalid fixtures с API и UI. `bool`/float/null не являются целыми таймингами.
- **Зависимости:** согласование контракта; не ждёт FFmpeg.
- **Передать:** Руслане для API, Леониду для UI, Андрею для рендера. Андрей и Руслана
  независимо запускают проверки Татьяны до merge.

## A2.02. `generate_tone` и `main`

**Файл:** `tests/fixtures/generate_tone.py`. **Статус:** реализованы.

- **Вход/выход:** `generate_tone(Path, duration_seconds=10) -> None`; CLI принимает
  путь и необязательный `--seconds`, пишет новый mono PCM WAV 16 kHz/16 bit.
- **Что сделать:** использовать генератор для 5, 10, 60 секунд и граничных тестов.
  Сохранить отказ от перезаписи файла. JSON `render-spec.json` соответствует 10 секундам.
- **Проверка:** Python `wave` подтверждает число каналов, частоту и frames;
  повторный запуск на тот же путь отклоняется. Команда есть в `tests/fixtures/README.md`.
- **Зависимости:** только Python; не нужен чужой трек или сеть.
- **Передать:** Андрею для CLI, Варваре для CI, Руслане для upload. Тон не проверяет
  вокал и ASR: отдельную разрешённую голосовую запись подготовить с автором.
