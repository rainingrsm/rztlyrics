# План приёмки v0

Владелец: Татьяна (A2 + QA). Каждый разработчик проверяет свои функции;
приёмка кода Татьяны - Андрей/Руслана. Это план будущих продуктовых проверок,
не отчёт о готовности. Результаты и SHA записываются в `test-report.md`.

## Среда и правила

- Отдельное тестовое окружение: свои volume/БД/каталог; не ломать демонстрационный стенд.
- Исходный fixture: `tests/fixtures/render-spec.json` и WAV из `generate_tone.py`.
  MP3 и голосовой пример с подтверждённым источником команда добавит отдельно.
- На каждом прогоне: SHA, URL/команда запуска, ОС, браузер/версия, дата, исполнитель.
- PASS только после наблюдаемого результата; FAIL со ссылкой на issue; NOT RUN если
  сценарий не запускали; BLOCKED с причиной, если отсутствует зависимость.
- P0: основной сценарий не работает/теряет данные; P1: обязательная функция неверна;
  P2: оформление/необязательное удобство. В релизе нет открытых P0/P1 основного сценария.

## Измерение и доказательства

Для T16 нужны эталонные времена и извлечённые кадры около границ, а не ощущение
«вроде совпало». 30 fps ограничивает разрешение кадрового сравнения. A1+A2 заранее
договариваются о методе и сохраняют измеренные значения в отчёте.
Для T17 указать CPU/RAM, настройки, длину входа, wall time и пиковую память;
цель ≤3 минут не объявлять достигнутой без замера на выбранном стенде.

Минимальный автоматический набор после реализации: unit-интервалы/ASS, API
доступ/ошибки/двойной job, настоящий короткий FFmpeg-рендер и один UI→MP4 E2E.
Текущий CI каркаса не является этой полной приёмкой.

Контрольные точки: 27 ноября T01+T08+T15 через сайт; 6 декабря законченный ручной
сценарий; 20 декабря release candidate; 27 декабря повтор на релизном SHA.
